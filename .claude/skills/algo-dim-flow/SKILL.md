# 算法维度流转梳理规则

边界：只管"如何梳理并呈现算法的维度变换流程"。何时写入 DESIGN/README 归
`doc-roles` 与 `readme-structure`，图的美化细节不在此展开。

## 1. 何时做

- 接手任何新项目：读懂数据与主流程后、动手改代码前，先产出维度流转文本。
- 顺序不可反：**先文本、经用户确认、后绘图**。文本没对齐就画图必返工。

## 2. 文本版纪律（硬规则）

- **形状真实完整**：每个张量写全部轴，禁止"同上/同前/…省略"。
- **每个非显然轴当场解释**：写成 `轴=含义`，复合轴要拆解
  （如 `9 = 3资源类型 × 3资源档`、`80 = 8纬度格 × 10经度格`）；
  已解释过的轴后文不必重复。
- **只讲内存张量，不提存储**：不写文件名/CSV/NPZ/分几个文件存；
  数据分文件保存时按堆叠视角写形状（9 个文件各 (8760,5) → 堆叠 (9,8760,5)）。
- **公式写全并给理由**：`(1/8760)·Σ v³（功率∝v³，按能量权重计年资源）`，
  禁止只写 `mean(v³)` 这类黑话。
- **派生量一句话定义**：标记、指标、汇总数等每个新量，
  先一句话说清（"修改标记：逐小时 0/1，1=值被移植换过"），需要时配迷你例子。
- **stage 划分**：每个 stage 一句话职责，其下每行一个变换 `操作 → (形状)`。
- **用算子语言**：gather / reduce / argmin / 逐元素映射 / 展平 / 排序切分，
  贴近深度学习表述习惯。
- **形状实测不脑补**：读文件打印 shape/dims 核实，与 CLAUDE.md"缺失数据不造"同源。

## 3. 图版纪律

- **图与文分工**：流程描述承载全部细节（公式、轴解释、配额规则）；
  图只画主干——层名 + 节点 + 输出形状，每个框文字 ≤2 行，
  绘制后必须目检防溢出，溢出即简化而不是缩字号。
- **首选分层网络结构图**（贴近深度学习习惯）：列=操作层，节点=圆圈，
  连线=数据流，输入层列真实输入变量，输出层展开到实体（如 3×3=9 库）；
  列下标注"层名 + 输出形状"，结构不变式一句话放脚注。
- 并行分支用泳道/分行节点表达；轴解释放列标注，不放节点内。
- 只画算法主线：校验、缓存、复核、画图等工程步骤不进图。

## 4. 标准动作序列

1. 实测输入：每个输入文件读 head + shape/维度，写出输入张量表（含轴含义）。
2. 通读主流程代码，逐段记录 `变换前形状 → 操作 → 变换后形状`。
3. 写文本版（按 §2 模板：输入 / stage 1..n / 总输出），交用户确认。
4. 确认后绘图，图嵌入项目文档（README 算法全流程章）。
